## 1. 产品气质与三条不可妥协

1. **工具感，不炫技**：这是一个本机单人工具，信息密度优先。用户来这儿是为了「快速把经历变成一份能投的简历」，不是来欣赏动效的。
2. **本地感必须可见**：界面要让用户随时确信「数据在我电脑上」。常驻的「本地 · 无云同步」标识 + 出网前字段清单，是这个产品的信任基础。
3. **发送前必须停一下**：任何 LLM 调用前，都有一次明确的、可读的、可取消的确认。这不是免责声明，是产品的核心机制。

## 2. 信息架构（5 个一级页面 + 2 个全局浮层）

```
左侧固定导航（宽 200px，可折叠至 56px）
├─ 🏠 工作台 Dashboard        —— 今天要做什么：3 个主动作 + 最近构建
├─ 📦 经历库 Warehouse        —— Package 列表 / 详情 / 变体编辑
├─ 🧩 模板 Templates          —— 模板列表 / 导入 / 区块与槽位编辑器
├─ 🎯 目标 Jobs               —— JD 列表 / 需求分析 / 公司画像
├─ 📄 构建 Builds             —— 构建列表 / 组装预览 / 导出
└─ ⚙️  设置（底部）           —— 个人信息 / LLM Provider / 关于与隐私

全局浮层
├─ 🔐 ConsentModal（LLM 发送前字段清单，模态，必须不可绕过）
└─ 📋 JobToast（长任务进度，右下角常驻卡片）
```

**顶层状态条（全局常驻，高 36px）**
- 左：`本地运行 · 127.0.0.1:8765`（点击复制 URL）。
- 中：`AI 已启用：DeepSeek / deepseek-chat` 或 `AI 未启用：未配置密钥（点击设置）`（灰底，可点）。
- 右：字体状态点（中文 PDF 可用=绿 / 不可用=红）、「最近导出」，末尾显示 **`build`（如 `b8c335e`，hover 提示「当前进程运行的代码版本；与仓库 HEAD 不一致说明需要重启」）**。理由：Python 不热重载，用户/复核者常对着旧进程看行为；把 `build` 常驻在状态条上，见面第一眼就能判断「这是不是当前代码」。

## 3. 页面级设计输入

### 3.1 工作台 Dashboard

**目的**：让用户在 5 秒内知道下一步做什么，而不是看空白列表。

- 顶部三个大动作卡（等宽，48px 高标题 + 一行说明）：
  1. **「从一段经历开始」** → 打开 `PackageForm` 抽屉（新建包）。
  2. **「导入我现有的简历」** → 打开文件选择（`pdf/docx/md/txt/html`），进入导入‑校对流程。
  3. **「针对一个 JD 定制」** → 打开 `JDWizard`（粘贴 JD → 分析 → 选包 → 导出）。
- 下方两栏：
  - 左「最近构建」：最近 5 条 `ResumeBuild`，显示 `name / 岗位 / 模板 / 页数 / 导出时间 / 状态`，行尾「打开」「重新导出」。
  - 右「库的健康度」：`verified 变体数 / 未验证数 / 无量化成果的包数 / 缺个人信息的字段数`，每项可点击跳到对应筛选。
- 空态（首次使用）：大号引导 + 「先填个人信息」按钮，因为缺 `name_zh` 会直接阻塞命名模板。

**硬要求**：工作台不得出现任何会自动触发 LLM 调用的按钮。

### 3.2 经历库 Warehouse

- 列表：卡片式（不是表格），每卡显示 `title · org · 时间区间 · kind 徽标 · verified 变体数 · 标签 chips`。
- 顶部工具条：搜索框（占位文案「搜经历、技能、公司…」，走 `?q=` FTS）+ `kind` 分段筛选 + `status` 下拉 + 「只看未验证」开关。
- 详情右抽屉（宽 560px）：
  - 顶部：标题（行内可编辑）、`kind/org/role/时间` 编辑区、`status` 切换（draft→ready 时若没有 verified 变体，按钮禁用并飘出说明）。
  - 主体：**Bullet 分组视图** —— 按 `bullet_key` 分组，每组一行「事实」，组内多列并排展示不同 `tone` 的 variant（impact/technical/leadership/concise/ats），可横向滚动。
  - 每条 variant：`text`（可编辑 textarea，auto-height）、`tone` 徽标、字符数、`verified` 复选框、`关键词` chips、`⋯` 菜单（删除 / 复制 / 用 AI 改写）。
  - 底部：「+ 添加一条事实」与「保存」。
- **「用 AI 改写」**：点击后不是立即调接口，而是先勾选「要改哪几条事实 / 生成哪些 tone」，然后弹 `ConsentModal`，确认后才调 `variants/generate`。
- 演示数据提示：列表为空时给 3 条示例卡（灰化，标注「示例，点击可复制为草稿」），可一键清除。

### 3.3 模板 Templates

三个 tab：`我的模板` / `导入中` / `内置示例`。

**导入‑校对流程（本项目最复杂的界面，请重点设计）**

```
① 上传 → ② 解析中（进度条 + 阶段文案） → ③ 校对（draft 编辑器） → ④ commit
```

③ 校对页布局：**左 60% 原 PDF 渲染预览（可缩略图逐页），右 40% 结构树**。
- 结构树每个 block 一行：`拖拽手柄 | 类型图标 | heading 或 preview_text | 置信度徽标 | 槽位数`。
- 置信度：`≥0.8` 绿点；`0.6–0.8` 黄点「建议核对」；`<0.6` 红点「需确认」。
- 点击某 block → 左侧预览高亮对应区域（若能用坐标；不能则至少高亮页码）。
- block 内联展开可编辑：`block_type` 下拉、`heading` 输入、槽位列表（`slot_key` 输入 + `bound_field` 下拉 + `required` 勾选 + 「建议值」按钮一键回填 `profile.*`）。
- 顶部警告条（来自 `GET /imports/{id}/draft` 的 `warnings[]`）：
  - `CID_GLYPH_MISSING` → 蓝色 info 条：**「已将 16 处 (cid:127) 项目符号还原为列表项」**（必须显示具体数字）。
  - `PHOTO_DETECTED` → 「检测到 1 张图片，是否作为证件照？」+「用作证件照 / 忽略」。
  - `LOW_CONFIDENCE_BLOCKS` → 黄色：「3 个区块置信度较低，请重点核对」+ 「只看这些」筛选。
- 底部固定操作区：`模板名称` 输入、`lang` 分段、`page_limit` 数字、（可选）「设为默认」→「保存模板」。

**区块与槽位编辑器（已 commit 的模板）**：树形拖拽 + 右侧属性面板（`style_json` 用表单呈现：字号/加粗/间距/分隔线/颜色），槽位以 chip 形式挂在 block 上。

### 3.4 目标 Jobs

- 左列表 + 右详情（主从布局）。
- 新建 JD：粘贴大 textarea（自动去多余空行，显示字符数）。`company_name` 与 `title` 可留空，留空时提示「影响命名模板 {company}/{position}，可稍后补」。
- 详情页两块：
  - **需求矩阵**：表格 `技能 | 类别 | 优先级(must/should/nice) | 权重条 | 命中包数`，每行可编辑（改后标「手动」徽标）。
  - **匹配度面板**：`覆盖率 71%` 大数字 + 环形图；`已覆盖` chips（绿）与 `缺口` chips（红）；下方「这些包最匹配 →」按钮跳到构建页并预选。
- 「分析」按钮：LLM 可用 → 先 `ConsentModal`（列出 JD 全文将发送 + 字数）；LLM 不可用 → 按钮变「用本地规则分析」，点击直接跑启发式，并提示「结果较粗，可在设置里启用 AI」。

### 3.5 构建 Builds

三栏：`左 260 选择器 | 中 预览 | 右 380 导出设置`。

**左侧选择器**
- 模板选择（下拉 + 「预览缩略」）。
- 目标岗位/公司（两个输入，带「从 JD 带入」按钮）。
- 包选择：按 `bound_package_kind` 分组（教育背景 / 实习 / 项目 / 奖项），每组内包卡片可拖拽排序，勾选加入。
- 每个已选包可展开选择**具体 bullet**（checkbox 列表，显示 tone 徽标与字符数），并显示「已选 4/6 条 · 92 字」。
- 顶部实时统计：`已选 3 个包 · 11 条 bullet · 预计 1.24 页`（超页变红）。

**中间预览**
- `iframe` 加载 `/api/v1/builds/{id}/preview`（服务端渲染 A4 页面，白底阴影）。
- 顶部工具：缩放（50/75/100/适应宽度）、页码跳转、字号微调（仅影响预览，不写库）。
- 缺失槽位：预览内对应位置显示橙色占位块 `⟨candidate.school⟩`，点击跳到右侧对应输入框。
- 照片位：有照片时右上角 89.3×89.3 pt 方块（约合预览中 24 mm）；无照片时姓名区自动占满整行——预览里**不能出现空白方块**，让用户误以为渲染出错（AC-PHOTO-02）。

**右侧导出设置**
- `format`：PDF / DOCX / Markdown（分段控件）。
- **命名**（走 `POST /api/v1/naming/validate`，边输边校验，**恒 200**）：
  - 输入框默认值 `{position}-{name}-{school}`，下方实时显示 `data.filename`（大号等宽字体）；实际产物名以服务端 `data.filename` 为准，前端**不自己拼**。
  - 变量 chip 行（7 个全给）：`{company} {position} {date} {name} {school} {version} {lang}`；可点击插入；灰掉表示当前上下文无值，点击显示 tooltip「取数来源：`profile.school_zh`（为空）」。
  - `data.valid=false` 时：红字显示 `errors[0].message` + 「去填个人信息」深链；主按钮**禁用**（缺变量绝不允许导出，见 ACCEPTANCE AC-NAME-04）。
  - `warnings[]` 用灰/黄小字逐条列出（`NAMING_SANITIZED`＝文件名已规范化、`NAMING_TRUNCATED`＝已截断、`NO_VARIABLE`＝不含变量、`NAMING_COLLISION_SUFFIXED`＝已另存为 -2）。
  - 变量明细（`data.variables[]`）折叠展示：每个变量的 `value` 与 `source`，让用户知道这个名字是从哪来的。
  - 「恢复默认格式」文字按钮。
- **照片开关**：`☑ 包含照片`，默认**开启**（读 `app_setting.photo_in_export`，单次可改）。
  - 有照片：开关下方显示 32×40 px 缩略图 + 「当前照片来自：本地上传 / 从导入简历提取」+ 「更换 / 删除」链接（跳个人信息页）。
  - **无照片**：开关置灰不可勾，下方一行灰字「未设置证件照。可直接导出（右上角自动重排，不会留空）」+ 「去上传」链接。**导出按钮保持可用**——绝不因为缺照片阻断。
- 高级（折叠）：`engine=auto/reportlab/chrome`、`overwrite`、`verify_text`。
- 主按钮：「导出 PDF」（>2 s 时按钮变 `JobToast` 进度）。

### 3.6 设置

四个区块：`个人信息` / `AI Provider` / `界面` / `关于与隐私`。

- **个人信息**：两列表单（中文姓名*、英文姓名、中文学校、英文学校、学历、专业、毕业年份、手机、邮箱、城市、到岗时间、证件照）。每个字段右侧小字标注「用于：命名模板 {name}」「用于：简历头部」——让用户知道这个值会去哪。
  证件照区域单独一行，三态：① **无照片** → 虚线框「上传证件照（png/jpg，≤5MB）」+ 说明「仅本机保存与渲染，不会上传给任何 AI」；② **有照片** → 96×120 预览 + 「更换」「删除」；③ **导入时发现内嵌图** → 在导入校对页出现候选卡片「检测到 1 张图片（266×266，疑似证件照）」+ 「设为证件照」/「忽略」两个按钮，选「设为证件照」才写库（`photo_source=imported`）。
- **AI Provider**：两张卡（**DeepSeek（推荐，默认）** / **OpenAI 兼容地址（高级）**）+ 顶部「AI 总开关（关闭=完全不上云）」。选中后展开 `base_url`（DeepSeek 卡只读默认值；兼容卡可改）、`model`、`API Key`（密码框，写入后只显示「已设置 · 更换」）。**不提供本地模型（Ollama）入口**——用户已定 DS 路线；需要完全离线时用总开关关闭，界面显示「AI 已关闭，全部本地功能可用」。
  - 每张卡下方状态行：`未配置` / `已配置，未测试` / `可达（3 个模型）` / `不可达：连接被拒绝`，右侧「测试连接」。
  - 关闭总开关后：Jobs/Company 页的分析按钮变「用本地规则分析」，ConsentModal 永不出现，顶部灰条「AI 已关闭 · 数据不出本机」。
  - Key 输入框旁必须写：「密钥仅保存在本机 `.env`，不会显示、不会写入日志、不会上传。」
- **联网与抓取**（放在「关于与隐私」上方，独立一行）：
  - `☑ 允许抓取公司官网与招聘页`（默认开启，对应 `allow_web_fetch`）。说明文案必须写清：「只读取公开网页正文，**不会发送你的任何信息**（请求里只有网址）；关闭后仍可用你粘贴的 JD 分析。」
  - 关闭时：Jobs 页的分析按钮旁显示「仅用粘贴内容」，抓取入口消失，不报错。
  - 抓取失败时：提示条「未能抓取 <host>（原因）。已改用你粘贴的 JD。」+ 「仍允许抓取」开关深链。
- **关于与隐私**：一句话架构说明 + 三个数字（`本地数据文件数`、`本月出网次数`、`最近一次出网时间`）+ 「查看出网审计」两个 tab：`上行（发给 AI）`（只有字段名、目标 host、token 数，**无正文**）与 `下行（抓取的公开页）`（只有 URL/host/状态/字节数，**无你的任何数据**）+ 「数据目录」可复制路径 + `.gitignore` 说明。

### 3.7 简历内容结构的四条用户裁决（**会反复被"优化"掉，写死**）

| # | 裁决 | 界面上的表现 | 禁止 |
|---|---|---|---|
| 1 | **荣誉不单独成节** | 留在「校园活动」下，作为可选 bullet（默认显示）；投研究岗时可勾选「把荣誉拎到前面」，但**节标题不变** | 不得新增「荣誉奖项」一级/二级标题；不得为它做独立卡片 |
| 2 | **小象超市那条不分竞赛** | 仍归在 `项目经历` 下（`bound_package_kind=project`），列表里不显示"竞赛"徽标 | 不得按关键词自动改分类；不得让用户"看着像竞赛"就拖到竞赛区（没有竞赛区） |
| 3 | **主修课程默认全留** | 导出选项里给一个开关「按 JD 精简主修课程」，**默认关**；开启后底部提示「已从 12 门裁到 5 门」 | 不得默认开；不得裁到 <3 门；不得连「主修课程：」前缀一起裁掉 |
| 4 | **职业技能不拆 tag** | 技能区**逐行原文**渲染（如「数据分析类：掌握Python、R、SQL等编程语言，可独立进行数据清洗、统计分析与可视化处理」），一个字不改 | **禁止** tag 块、标签云、`Python / R / SQL` 这种竖线分隔的短词块、禁止"技能雷达图"。理由：用户原话「HR 看到一堆 tag 不知道具体情况，会莫名其妙」 |

> 编辑态（个人信息页）可以为每行技能显示「分类」输入框与只读的「匹配用词」小字（来自 `tokens`），但要明确标注「仅用于匹配，不会出现在简历上」——否则用户会以为简历里会长出 tag。

### 3.8 版式密度（两档，设计稿必须按它画；数值来自用户原件实测）

**别再按「通用简历模板」的 15–20 mm 边距设计**：用户原件是 **5 mm 级**密度。若按通用值排，同一份内容会从 1 页变 2 页——对用户是可见退步（ADR-21）。

| 参数 | `density="original"`（**默认**） | `density="relaxed"` |
|---|---|---|
| 页边距（上/下/左/右） | **8.3 / 16.4 / 14.8 / 15.6 pt** | 16 / 16 / 15 / 15 mm |
| 可用高度 | **817.65 pt（288.4 mm）** | 751.5 pt |
| 版心宽 | **564.9 pt（199.3 mm）** | 510.5 pt |
| 字号阶梯（字/p 行距比） | **11.0/1.15** → 10.5/1.15 → 10.0/1.15 → 9.5/1.15（末档紧急） | 同左 |
| 行距比 | **1.15**（11 pt ⇒ ≈12.65 pt） | 同左 |
| 目标 | 单页，正文**中位 ≥ 10.5 pt** | 允许 2 页（必须告警） |
| 证件照 | **89.28 × 89.28 pt**，距顶 3.82、距右缘 9.13 | 同左，**不随降档缩放** |

设计要求：

1. **预览区版心按 `original` 画**（可用高度 817.65 pt = 288.4 mm）；设计稿里任何 px 值只是某一档示意，**真实基线由 t8 首份 PDF 产生**（证据等级：估算，ARCHITECTURE §7.5.2）。
2. **降到 10pt 要有可见提示**（`PAGE_FIT_DOWNGRADED`）——一行常驻说明，不要只弹 toast。
3. **两页兜底要显式**（`PAGE_OVERFLOW_TWO_PAGES`）：提示「已排到 2 页（超出 X pt）」+「精简要点」入口。
4. **不要为了塞一页去缩照片、缩边距、压行距**：反作弊下限 = 正文字号中位 **≥10.5 pt**、行距比 **∈[1.10,1.25]**、页边距 ≥ `original`（见 ARCHITECTURE §7.5.1 规则 3）。设计稿若出现更紧的数值，视为规格违规。
4b. **条目头必须单行**：`org · role …… 日期` 同行渲染，日期列占 **12%–22% 版心**（67.8–124.3 pt）。**不要把 org / role / 日期各占一行**——那会把每条目从 1 行涨到 2–3 行，正是「33 行变 45 行」的主因（ADR-22）。
4c. **`print.css` 的 `--doc-leading` 取值必须与契约同源**：`--doc-leading: 1.15`（对应 `leading_ratio`），`--doc-body: 11pt`。**禁止**在 CSS 里另写一套阶梯（Swift 漂移源）。旧值 1.62/1.50/1.45 一律废弃。
5. **`facts`（教育段整段文字）按整段排版**，行首无项目符号；不要拆成 bullet。

**导出页的语言提示（v1.8）**：导出时若 `warnings` 含 `LANG_FALLBACK`，在结果区顶部渲染一行**常驻**提示（非 toast）：「以下 3 个条目没有英文版本，已沿用中文原文 — 可在仓库补英文要点」。含 `LANG_HEADING_UNMAPPED` 时提示「自定义标题『科研经历』未映射，已按原文输出」。两者都是**信息**不是错误，导出照常完成、下载按钮保持可用。

### 3.9 变体的「事实 / AI 改写」二分（**视觉必须一眼可分，不许只靠颜色**）

来源：导入自己的简历时，原文要点与模型改写要点会一起进仓。二者可信度不同，**UI 必须让人在不读小字的情况下分辨**。

| 变体状态 | 角标文案 | 展示位置 | 默认勾选 | 为什么 |
|---|---|---|---|---|
| `verified=1`（**原文即事实**） | `原文` | 要点行**左端**，实线细边框 | ✅ 是 | 用户自己写的既成事实，无需二次确认 |
| `verified=0`（AI 改写） | `AI 改写` | 要点行**左端**，**虚线**细边框 | ❌ 否 | 未经人确认的新语句，不得冒充事实；勾选后角标变 `已确认` |

硬要求：

1. **形状差异而非纯颜色差异**（色盲可用）：原文=实线、AI=虚线；**角标文字必须不同**（`原文` / `AI 改写`），不允许只用两种颜色区分。
2. `verified=0` 的要点**默认不进入**选中集合；用户勾选时**不弹二次确认**（避免打断），但角标立刻变为 `已确认` 且写入 `verified=1`。
3. Builds 预览里，`verified=0` 且被取消勾选的要点**不得渲染进 PDF**；不得出现「灰掉的占位行」——那会让用户以为简历里真有这一行。
4. 导入校对页提交时若存在未确认的 AI 改写，**不阻断**，只在提交按钮旁提示「N 条 AI 改写未确认，不会进入导出」。

## 4. ConsentModal（全局唯一出网闸门，最高优先级）

**触发时机**：任何 `POST /llm/preview` 成功后立即弹出；**没有它，`/llm/complete` 不允许被调用**（前端不得存在其它调用路径）。

**布局（宽 720px，最大高 80vh，内容滚动，头尾固定）**

```
┌─ 将发送以下内容到 DeepSeek · deepseek-chat ────────────────────┐
│ 目标地址 api.deepseek.com ｜ 约 812 tokens ｜ 10:51 后失效      │
├───────────────────────────────────────────────────────────────┤
│ 将发送 4 项（共 1,284 字）                                     │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │ ☑ 系统指令（内置）                        42 字 · 30 tok  │ │
│ │ ☑ 简历片段 · 订单中台重构 · impact         74 字 · 48 tok  │ │
│ │ ☑ 简历片段 · 订单中台重构 · technical      96 字 · 61 tok  │ │
│ │ ☑ 你的附加要求                            16 字 · 12 tok  │ │
│ └───────────────────────────────────────────────────────────┘ │
│ 不会发送（重要）                                               │
│ · 未选中的 10 个 Package、39 条变体                            │
│ · 你的姓名 / 手机 / 邮箱（替换为 [NAME][PHONE][EMAIL] 发送，    │
│   真实值只在本机导出时回填）                                    │
│ · 你的证件照（照片字节永远不上传）                              │
│ ── 会发送（用于分析）──                                        │
│   ✔ 学校名、学历/专业/届别、城市、到岗时间                       │
│   ✔ 你选中的经历/项目片段、JD 原文、公司名与岗位名               │
│   ✔ 参与对照的 7 条经历要点（包标题 / 时间 / 要点文本，         │
│     最多 12 个包、6000 字；超限会显示「已截断 5 个包」）          │
│ · 导入的简历原件（2 个私有文件始终不参与）                     │
│ ▸ 查看完整请求体（JSON）                                       │
├───────────────────────────────────────────────────────────────┤
│                              [取消]  [确认发送（约 812 tok）]  │
└───────────────────────────────────────────────────────────────┘
```

**交互细节（全部硬要求）**
1. `fields[]` 的每一项都必须渲染 `label + chars + est_tokens`，`included=false` 的置灰并说明为什么（如「已脱敏移除」）。
2. `excluded.note` 与 `excluded.skipped[]` 必须在**主视野**（不折叠）。
3. `redactions[]` 有内容时用黄色块，并显示 `value_preview` 与替换值。**每条替换值必须是占位符**（`[NAME]`/`[PHONE]`/`[EMAIL]`/`[ID]`），必须让用户一眼看到「发出去的是占位符，不是真名」。**学校名不脱敏、不会出现在 `redactions[]` 里**——不要为了「看起来更安全」把校名也抹掉，那会削弱定制效果（用户已明确要求真实校名参与分析）。
3.1. 固定一行说明（不可折叠、用大白话，不堆术语）：「**不会发送**：你的姓名、手机号、邮箱、证件照。**会发送**：你的经历与项目片段、JD 原文、公司名与岗位名、学校名、学历专业届别。姓名和联系方式在发送前已替换成占位符，导出时自动换回真实信息。」
3.1b. **「会发送」清单必须包含经历要点条数，且可展开逐条核对**（v1.9，§6.2.3）：显示「**N 条经历要点**（项目/实习标题、时间、要点文本）」，N == `context.packages_included`；点开展示 `fields[]` 里 `source="packages"` 的每一行。**只显示总数、不给清单 = 让用户盲签**。超限时同一位置显示 `PACKAGES_TRUNCATED` 的 `{included, skipped}`（灰字，不阻断）。
4. 「查看完整请求体」默认折叠；展开后 `<pre>` 只读、可复制。
5. `Esc` 或点遮罩 = 取消（调 `reject`），**不允许**把 Enter 绑定到「确认发送」。
6. 确认按钮文案必须含 token 数与 provider/model；点击后按钮进入 loading 并禁用，防重复提交。
7. 过期（`expires_at` 到）→ 模态内容变灰，按钮变「重新生成预览」。
8. 发送失败（`LLM_*` 错误）→ 模态不关闭，在底部显示错误条 + 「重试（同一次发送）」/「取消」。

## 5. 全局状态、空态、错误

| 场景 | 界面 |
|---|---|
| 首次启动、库为空 | 工作台引导式空态；Warehouse/Templates/Builds 各自空态文案 + 一个主按钮 |
| 中文字体不可用 | 顶部红色条：「中文字体缺失，PDF 导出已禁用（可用 DOCX）」+ 「查看体检报告」 |
| AI 未配置 | 顶部灰条（可关闭当次会话）：「AI 功能未启用」+ 「去设置」 |
| 长任务 | 右下 `JobToast`：进度条 + 阶段文案 + 「取消」（仅 queued 可取消）+ 完成后可点「打开产物」 |
| 页面溢出告警 | 预览顶部黄条：「预计 1.24 页，超出 1 页限制」+ 「自动精简」（去掉最短的 2 条 bullet 后重新组装） |
| 无证件照却要导出 | 不阻断：预览右上角无图，导出设置里开关置灰并给「去上传」；产物正常生成（AC-PHOTO-02/04） |
| 抓取被关 / 抓取失败 | 提示条「仅使用你粘贴的 JD 分析」+ 开关入口；分析照常进行（AC-FETCH-03） |
| PDF 文本层校验失败 | 产物卡片红色角标 + tooltip：「该 PDF 文本可能无法被 ATS 正确解析（3 处差异）」+ 「改用 DOCX」 |
| 服务重启导致任务中断 | JobToast 变灰：「任务已中断，可重试」 |
| 后端不可达 | 全屏骨架 + 「无法连接本地服务（127.0.0.1:8765）」+ 「重试」+ 「查看启动说明」 |

**错误展示规则**
- `422/409/428/410`：内联（表单下方/字段旁），用 `error.code` 分支，用 `error.hint` 作为下一步建议。
- `5xx`：toast + 「复制诊断信息」按钮（复制 `request_id` + `code`）。
- 永不把 `details` 原样 `JSON.stringify` 丢给用户。

## 7. 文案基调

- 用动词开头的短句：「导入已有简历」「针对 JD 定制」「导出 PDF」。
- 不说「AI 赋能」「智能体」，说「AI 改写」「用本地规则分析」。
- 失败文案三段式：**发生了什么 → 为什么 → 我能做什么**。
  - 例：「PDF 导出失败。Chrome 回退渲染也未成功。可以改用 DOCX 导出，或查看体检报告。」
- 隐私文案必须具体，不写「我们保护你的隐私」，写「手机号与邮箱不会发送；导入的简历原件不会发送」。

## 9. 硬约束（违反即打回）

1. **零外部资源**：不许 CDN、Google Fonts、远程图片、`<script src="https://...">`、外部图标库。图标用内联 SVG。页面在断网下必须完全正常（除 AI 功能）。
2. **零构建**：不引入 npm/打包器/TS 编译。浏览器直接跑 ES modules。目标：Chrome 最新版。
3. **禁止 `innerHTML` 拼接用户内容**（简历文本、包名、公司名、JD 都是用户可控的 XSS 载体）。用 `textContent` 或统一的 `escapeHtml()`；预览统一走服务端渲染的 `/preview` 页面（jinja2 已 autoescape）。
4. **Consent 不可绕过**：前端不存在「跳过预览直接 complete」的代码路径；`panel`/`dev` 也不加。
5. **颜色不是唯一信息载体**（置信度、优先级、警告都要有文字或形状）。
6. **对比度** ≥ 4.5:1（正文）；焦点环必须可见（`outline: 2px solid` 自定义）。
7. **中文排版**：正文行高 ≥ 1.5；数字/英文与中文之间不强制加空格，但同一页内要一致。
8. **不显示任何密钥片段**，不做「显示密码」的明文切换（只在写入时可见）。
9. 响应式下限：1280×800 完整可用；1440+ 三栏展开；不支持手机竖屏（可提示「请用桌面浏览器」）。
10. 打印：预览页 `@media print` 必须等于 PDF 的 A4 版式（margin 与字号一致），方便用户 `⌘P` 兜底。
